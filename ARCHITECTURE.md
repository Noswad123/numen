# Numen architecture

## Overview

**Open chat via Wisp:** implemented, not installed or desktop-accepted; earlier installed/test evidence below is historical for this feature. It requires updated Numen and Djinn Rust/UI, with an explicit older-Djinn restart still outstanding; Wisp code is unchanged. Discovery/Attach still cannot execute source commands; only an explicit Open chat selection submits the fixed viewer-launch path described below.

**Wisp migration:** native **Palette** key **n** now dispatches bare Numen via
`exec`; Kitty/fzf is only the explicit secondary `wisp menu` / advanced
`numen menu` path. [Canonical contract and status](WISP.md) distinguish code
checks, confirmed installations/native exec reuse smoke, and manually updated
on-disk configuration. The authorized AeroSpace reload is confirmed (main alt-c removed, shift-alt-c preserved); physical key/focus acceptance remains manual.
Older installation/no-home-edit reports retain their historical scope;
historical “palette → Kitty” refers to the old CLI selector, now `wisp menu`.

**Current product contract — unattached-first:** bare `numen` opens one unattached view through the existing GUI service or bounded empty bootstrap; repeated launches reuse the service, up to 16 views. `numen run` remains foreground with unattached Main. Production GUI disables `auto_select_main`; only legacy headless/test constructors retain compatibility auto-selection. Source registration/state/reconnect/expiry never attach unbound graphical views; existing exact pins keep reconnect/availability semantics. Historical attached-only Open and user-UI auto-selection descriptions are **SUPERSEDED**, not active design.

**Delivery confirmed:** the latest debug binary is installed; final installed registration/normal-cleanup and interop checks passed. Final read-only doctor found the default service `not_running` and started nothing; use bare `numen`, then Option+C. The earlier older-reachable-service report is historical. Only if an older service is running later is an explicit user-chosen Numen restart needed, never automatic replacement or a Djinn restart. See [canonical current evidence and manual limits](README.md#optionc-validation-and-deployment).

Delivered: the Rust/macOS-first multi-familiar foundation, Go to mouse, familiar-first fzf menu, opt-in Wisp action installer, menu Open empty bootstrap, graceful graphical quit and runtime per-view presentation settings. Each view represents one exact activity, not aggregate work. Native lifecycle/navigation and real fzf PTY smoke tests passed; actual Wisp palette → Kitty handoff remains manual. The optional sibling Djinn owning-Worker interactive adapter publishes activity and authoritative response outcomes; its real idle-chat TUI → fzf → Metal handoff smoke passed (see README), not live outcome-animation acceptance. The additive [local v1 protocol](PROTOCOL.md) is not a stable public SDK; other platforms/compositors and further hands-on desktop acceptance remain unvalidated.

Sources report semantic activity, not artwork or executable scripts. The process keeps transport, activity reduction, personality mapping, and rendering separate. Live activity, registry and pins remain ephemeral, without durable activity history or a broker. Production live GUI startup now enables the separate saved appearance/manual-placement store described below.

## Data Flow

CLI file/stdin batches: bounded raw bytes → `ipc::parse_unique_json` → JSON root array → request validation → service I/O. Duplicate keys at any object depth reject before JSON-value conversion can erase them; identical key names in independent valid rows remain allowed. `main::read_batch` is shared by Open and Attach.

```text
diagnostic publisher / future adapters
  -> newline-delimited JSON over private Unix socket
  -> request validation -> connection-scoped source/activity store
  -> per-familiar exclusive binding + base/cue + summary cache
     -> complete Vec<FamiliarPresentation> -> latest-only mailbox -> winit wake
         -> App reconciliation -> independent FamiliarViews -> pixels surfaces -> compositor
     -> legacy main presentation -> headless latest-only mailbox -> detached JSON stdout writer

Option+I Carbon callback / companion.reveal worker callback
  -> RevealNotifier / bounded RevealMailbox -> coalesced winit RevealBubbles
  -> App::apply_reveals -> selected views' visibility deadlines + native geometry
```

`run` starts the service by default. `--manual` and `--demo` disable socket creation. `listen` uses the same service without a window or asset decoding. `publish` also bypasses asset decoding: it registers, sends state changes, holds each with one-second heartbeats, then removes its activity and disconnects. It is an interactive diagnostic that returns errors, not automatic best-effort integration.

### Service and reduction

The worker polls every 25 ms, with one bounded read and at most eight messages per client per tick. Nonblocking I/O and bounded input/output buffers prevent one peer from blocking the service. Connection capacity includes unregistered peers. Registration, EOF drain, and liveness deadlines bound incomplete clients; details are in [Protocol](PROTOCOL.md).

The store tracks producers once and holds up to 16 familiars, attached or unattached. Ownership is exclusive by exact `(source, instance, activity)`, including disconnected reserved pins. Production `start_graphical_with_preferences` explicitly disables Main auto-selection even without saving enabled; compatibility constructors alone retain it. Source events never bind unbound GUI views. Exact pins persist through removal/disconnect/expiry without fallback; the same exact record can satisfy them again. Focus/next remain explicit selection controls; a new producer instance needs explicit selection. No OS-focus inference.

`main` remains the legacy default scope, not an alias for whichever view remains. Closing it does not recreate it: legacy status reports null focus, explicit unknown IDs error, and focus requires a valid existing ID. Generated `familiar-N` IDs are lifetime-monotonic without generated-history growth. Closed IDs cannot be reused; explicit history is bounded to 256 plus reserved `main` (257 total). No persistent profiles exist; restart resets IDs.

Open allows target-free and flattened targeted entries in one atomic batch; Attach requires targets. IDs/presets/capacity and all supplied targets validate before mutation. Duplicate IDs/targets, unavailable/ambiguous targets or ownership conflicts reject the batch. Attach cannot swap another owner's target. Close validates every ID first. Only preset `djinn` exists; sources are never executed/stopped. Direct CLI/wire Open needs a running GUI; bare launch and menu Open/Open attached… may bootstrap. Headless discovery is supported, GUI lifecycle is not.

### Menu, bootstrap and quit

The opt-in Wisp action is `kind = "exec"`, key `n`, with absolute argv `[executable, "--socket", resolved_absolute_socket]`, no `menu`. Native Palette dispatches the same bare-launch path as standalone Numen; repeated calls add independent unattached views in one service, max 16. Leading `--socket` avoids Wisp's work-directory heuristic; no PATH lookup or terminal is needed. Explicit `numen menu` requires Wisp `run`/`summon`, not exec. See [Wisp](WISP.md) for Palette/compositor ownership, stable old-daemon delegation of `wisp menu`, strict installer conflicts and recovery; no new protocol/restart is needed just for the Wisp rename.

`menu` requires stdin/stderr TTYs. Sanitized labels are display-only; typed `familiar:` / `preset:` IDs drive selection. fzf options/command environment overrides are removed; output is capped at 64 KiB and unoffered/duplicate identities are rejected. The menu intersects capabilities across the whole selection, preserves selection on command Back, discards all pending targets on target Back, and exits after one accepted command. Each target picker reads fresh four-row pages, filters other owners and locally reserved earlier choices, then submits one batch for server revalidation. Discovery alone performs no startup or filesystem writes.

Bare launch and offline menu Open/Open attached… call `ensure_graphical` (menu `--no-start` opts out). Bootstrap reuses compatible GUI services or launches current-executable `--socket PATH run --empty` with null stdin/stdout, private 0600 log stderr and `setsid`. Readiness is bounded to five seconds, control-only; concurrent starts reuse the UDS winner. Failure cleanup owns only its spawned child, never a metadata PID. Bare launch checks root v1 `unattached_open` and seals its one-item target-free Open to `service_instance`; missing legacy flag means false/manual-restart error, never replacement. Direct CLI Open requires a running GUI; read-only discovery/controls never bootstrap.

`Server::start_graphical_with_settings(path, on_views, on_reveal, optional_on_go_to_mouse, on_quit, bootstrap_main, settings: FamiliarSettings)` remains available without preference I/O; production uses the additive preferences constructor below. Defaults validate before listener creation. Legacy `#[cfg(test)] start_graphical` omits settings and rejects edits, but includes quit; other old constructors retain their compatibility behavior. `bootstrap_main = false` uses an empty store: no `main` is created even as sources arrive. `run --empty` conflicts with manual/demo. `companion.service` returns API version 1, PID, unique per-listener `service_instance`, graphical/lifecycle/navigation/settings/preferences booleans, logical familiar/source counts and versioned diagnostics without source changes or liveness refresh; there is no shutdown flag. Familiar rows separately advertise installed capabilities. The menu pins that instance and includes it on every RPC. Mismatched optional root preconditions reject before dispatch/callback/liveness mutation; old one-shot clients/producers may omit them. A restarted service cannot inherit stale selected IDs. The generation marker is not an authentication secret.

`companion.quit` requires the graphical shutdown callback. The worker schedules it after flushing the ACK and client EOF (or 500 ms after flush), ignoring later pipelined input. A coalesced `AppEvent::QuitService` exits the root event loop even at zero windows; hotkey/server drop releases registration, worker and owned socket, and all views are dropped. ACK `quitting: true` means scheduled, not completed. No source app is stopped and no reported PID is killed. Per-view Close still retains the service after last-close; cancelled menu Open may leave an empty resident service for explicit `quit`.

`Presentation.base` is only that focused record, including terminal identity; it is absent when the pin is unavailable. Only fresh focused success/failure transitions can create 1.5-second cues. Repeated terminal states do not replay; active failure cues outrank success cues, and focused attention drops cues rather than deferring them. Registration, snapshots and explicit selection never replay historical outcomes. Background updates remain queryable without affecting presentation. Idle and disconnect never imply completion.

Controls work without registration and do not refresh producer liveness. Status/focus/next accept optional `familiar`; reveal accepts optional `familiars`. `familiar.list` and `companion.targets` provide four-record pages; GUI capabilities are `info`, `attach`, `close`, plus `go-to-mouse` only with a navigation callback, while headless/legacy rows advertise `[]`. Targets are connected protocol-advertised activities with `claimed_by`/`eligible`, not OS scans or an actual Djinn adapter. See [Protocol](PROTOCOL.md) for response shapes. All prior 8 KiB framing, 16-source/24-client and transport bounds remain. GUI `FamiliarControl::next(id)` and `close(id)` use a nonblocking 32-entry channel drained at most eight times per worker tick. ACK confirms acceptance, not rendering; async native/GPU creation can fail after an Open ACK.

### Saved preferences: interfaces and data flow

The production caller in `window.rs` resolves preferences **only for live GUI startup**: `run --no-preferences` returns before environment/default resolution; `--preferences-file ABS` selects an explicit absolute override and conflicts with it. Otherwise `preferences::default_path(config_home: Option<OsString>, home: Option<OsString>) -> Result<PathBuf>` uses nonempty absolute XDG_CONFIG_HOME + `/numen/preferences.json`, else absolute HOME + `/.config/numen/preferences.json`. Relative roots and missing HOME produce distinct cached reasons. Manual/demo/headless do no preference I/O. Existing constructors never start resolving HOME or reading preference files.

`Server::start_graphical_with_preferences(path: &Path, on_views, on_reveal, on_go_to_mouse: Option<Box<GoToMouse>>, on_quit, bootstrap_main: bool, settings: FamiliarSettings, preferences_path: Option<PathBuf>) -> Result<Server>` extends the existing graphical-settings arguments. `None` retains runtime Settings but disables preferences. Defaults validate before listener creation. `preferences::start(path: PathBuf, on_status) -> (Document, Writer)` owns file work on a dedicated worker; its bounded startup result seeds the canonical activity Store. Status callbacks update `RuntimeDiagnostics`, not windows. The previous `start_graphical_with_settings` and compatibility constructors retain their behavior with no preference-file I/O.

`preferences::Document {version,records}` contains `Record {source,activity,settings: FamiliarSettings,placement: Option<Placement>}`; `Key {source,activity}` deliberately excludes instance and familiar ID. `Placement {x:f64,y:f64}` is sprite foot-center in desktop logical coordinates, finite inclusive ±1,000,000 (negative allowed). **Assumption:** a producer's activity IDs identify the same logical chat across instances. No title/prompt/summary, exact pin, open-window list, autostart, cue, pause or navigation state is written. Version 1 permits at most 128 records / 256 KiB and rejects unknown/duplicate object fields and duplicate logical keys.

```text
explicit Settings / completed manual drag
  -> bounded GUI control or validated wire Settings
  -> canonical Store runtime edit + logical-key document revision
  -> one pending immutable document -> background writer (one in flight)
  -> cached accepted/durable status -> companion.service -> read-only doctor

bounded startup document -> Store lookup on explicit Open / bootstrap first selection
  -> complete FamiliarPresentation {id,preset,presentation,settings,preference?}
  -> GUI reconciliation -> independent live style and bounded initial restore
```

`FamiliarPresentation.preference: Option<PreferencePresentation>` carries `{binding: PreferenceBinding {target: FocusTarget {source,instance,activity},generation},placement,writable}`. This full runtime tuple/epoch is **not** the persisted key, and never serializes into `Document`. `FamiliarControl::placement(id: &str, binding: &PreferenceBinding, sequence: u64, placement: Placement) -> Result<()>` and `forget_preferences(id: &str, binding: &PreferenceBinding) -> Result<()>` share the existing bounded nonblocking channel. Queue acceptance and wire ACKs mean acceptance, not durable storage.

Targeted Open applies saved style/placement or immutable startup defaults. Unattached Open uses defaults, has no logical preference key and never loads/saves chat preferences; its edits are runtime-only. First manual Attach uses the same policy as later Attach/focus/next: preserve live style/location, do not load destination preferences, associate new subsequent explicit edits with the selected key. Production Main never source-auto-selects. Same-key instances remain independent live views; remembered edits never autoapply to siblings.

Only explicit Settings and actual completed manual drags remember data. Drag capture freezes the full binding, generation, monotonic sequence and completed foot-center; retry never samples subsequent navigation/layout geometry. Attach and Forget invalidate queued stale work. Forget removes saved style **and** placement, leaves current settings/native position unchanged, and bumps epochs for **all** shared-key views even if the record is absent. Native Forget freezes/rechecks the original menu binding. CLI/wire validates the entire explicit ID batch before mutation. Close retains records; Forget never immediately auto-resaves, but later new explicit edits/drags can remember again.

Initial native placement restores once per new view, with bounded asynchronous native-size/DPI feedback: one-second deadline, at most five actual corrections, 20 ms polling. Each available monitor rectangle is converted using **its own** backing scale before logical clamping, including negative desktop coordinates. Restoration requests no focus. Go to Mouse/programmatic movement, clamping, layout, resize, close and source events never persist placement; restore/clamp/resize feedback is not treated as a manual drag.

### Saved preferences storage and recovery

- The normal config ancestor must already exist; missing ancestors are not recursively created. HOME/config/dotfile **ancestor** symlinks are allowed. Only the owned non-symlink 0700 leaf is created/accepted; the JSON/lock/storage files must be owned, non-symlink, single-link regular 0600 files. Existing unsafe nodes are not chmod-repaired or overwritten.
- Absent JSON is not created until the first remembered edit, though startup may create the leaf/lock. Malformed/future/oversized/unsafe input retains its bytes and disables saving; runtime defaults/settings continue. Nonblocking `flock` admits one writer; the second can load read-only. There is no merge/live reload, and detected external edits stop saving.
- Startup waits at most 200 ms and disables late load after timeout. The worker holds one pending plus one in-flight document, debounces 250 ms with maximum dirty delay two seconds, and uses a 500 ms shutdown budget. No file I/O on GUI/source IPC hot paths; OS syscalls already in flight are not portably cancellable. Pending/accepted revision does not mean durable.
- Capacity declines only a **new remembered key**; runtime edits still apply, existing keys remain editable and nothing is evicted. Cached `capacity_reached` remains sticky when only a partial accepted subset is durable, rather than falsely reporting all edits saved.
- Publication retains an immutable baseline, a stable snapshot and the displaced live inode, with **one bounded backup generation plus stage**, not unlimited history. Descriptor-relative/no-follow checks and NOREPLACE publication preserve conflicts; this is preservation-first, **not atomic CAS**, and the pathname can briefly be absent. External replacement/content/identity changes stop publication rather than merge. Rollback is no-clobber and never overwrites a recreated external path.
- Default artifacts are `.preferences.json.lock`, `.preferences.json.stage`, `.preferences.json.snapshot`, `.preferences.json.live` and possible `.preferences.json.quarantine` (derived from the selected filename). Recovery/quarantine conflicts require **manual inspection/cleanup**. Stop old-FD writers/editors, inspect current JSON and both backups, preserve/merge newer data, and only then restore or retire reviewed artifacts; never blindly overwrite current data with a snapshot. Old-open-FD writes are preserved for a bounded generation, not forever. Forget is **not secure erasure** of backup copies. This is not a defense against arbitrary malicious same-UID interference.

Root service `preferences` and bound-row `preferences` capability advertise writable support independently of settings/navigation; the row capability supports current Forget. `diagnostics.v1.preferences` is optional cached `preferences::Status`; doctor validates it without resolving/loading files. Current headless and old-constructor paths report **known disabled status**, with no preference I/O; a missing field from an **older binary** remains unknown, not inferred disabled. Exact mode/load/write/reason fields and session accepted/durable counters are in [Protocol](PROTOCOL.md#saved-preferences).

**Publication-race hardening confirmed:** backup retirement first moves the actual backup entries into a private quarantine and verifies inode/content against the immutable baseline before removal, preserving externally changed backups instead of unlinking a raced public name. Prepublication bad-node failures use no-clobber rollback. Flush tracks its requested revision target rather than conflating unrelated future edits; capacity warnings remain sticky when only a subset is durable. These fixes do not expand the documented threat model into arbitrary malicious same-UID protection, indefinite old-FD retention or atomic CAS.

**Validation/delivery:** main-agent confirmation is **367 passed (323 unit + 7 build-fingerprint integration + 37 CLI), one existing visual-preview test ignored**; formatting, strict all-target Clippy and offline locked tests/build green with the command-scoped SDK workaround. The private Apple Metal GUI harness (`np-rFEeeD/evidence.json`) passed five service cycles with read-only `CGWindowBounds`: seeded style 0.75/font 16/duration 1 and foot `(900,700)` restored at native hidden 216 × 234; explicit style 1/font 18 became durable without losing placement; restart A → B source instance created no views on registration, then explicit Open restored native 288 × 312 at the same foot. Forget became a durable zero-record document without changing live style/location; next restart/Open used startup fallback 0.5/font 14/duration 2 without file writes. Corrupt JSON stayed unchanged/read-only/rejected while runtime font 20 worked. Opt-out reported disabled/null path, skipped an absent XDG root and allowed runtime font 17 without touching the bad file. All five services quit 0 and removed their sockets. See [full evidence matrix](README.md#saved-preferences-validation-status).

Placement was preseeded: **no actual OS drag** or physical drag-save end-to-end acceptance is claimed. ### Read-only doctor data flow

Client `current_exe()` + embedded `build_info::current()` → one `ipc::control(companion.service)` → private socket/bounded ACK parser → validated service facts → human or single JSON report. No startup, process signaling, directory/log creation, reveal/settings/registration changes or producer TTL refresh occurs. Counts are `Store::familiar_count()` / `source_count()`, logical registry entries and registered sources, not native windows/processes. The service's PID/path/build are its own reported facts, not inferred from the client's path or package version.

`Server::diagnostics()` clones the actual shared `RuntimeDiagnostics` handle (`Arc<Mutex<Snapshot>>`); `window::register_shortcuts` publishes gates, pending and independent registration outcomes through it. The worker snapshots current values and releases the lock before serialization. This avoids freezing pre-registration startup status. Headless reports unavailable/headless. Exact version-1 schema, allowed state/reason pairs, legacy/future handling and JSON field names are in [Protocol](PROTOCOL.md#read-only-diagnostics).

Missing/refused sockets are informational `not_running`; absent diagnostics means `legacy`; future versions mean `unsupported_diagnostics`. These and different builds exit 0 with unknown facts where appropriate. Unsafe paths, timeouts, protocol errors, malformed current diagnostics, contradictory known state/reason combinations and duplicate JSON keys fail with exit 1. No rejected peer strings are echoed. Hotkey registration status is not evidence of OS chord delivery.

### Recorded build identity

`build_support::source_fingerprint` hashes sorted relative paths and contents of `Cargo.toml`, `Cargo.lock`, `build.rs`, `build_support.rs`, and recursive `src/` + `assets/` files. Symlinks/nonregular inputs are rejected. Versioned, length-delimited FNV-1a-128 produces `numen-inputs-v1-fnv1a128:<32 lowercase hex>`. `build_fingerprint` adds that checksum, sorted configuration and `RUSTC -vV` output to produce `numen-build-v1-fnv1a128:<32 lowercase hex>`.

Configuration covers target, profile, opt/debug settings, `CARGO_ENCODED_RUSTFLAGS`, and present `CARGO_CFG_*`, `CARGO_FEATURE_*`, `CARGO_PROFILE_*` values. Build-script watches include source inputs, common profile overrides and compiler/toolchain environment. Only hashes and bounded public version/target/profile labels are embedded for reporting; flags/compiler output stay hashed. No Git status/commit, timestamp or new dependency is used.

`BuildInfo {version, fingerprint, source_fingerprint, target, profile}` comes from the reporting executable's embedded constants. `build_info::compare` compares recognized build fingerprints with the current client's; serialized `build_comparison` is `match`, `different`, or `unknown`. Match means recorded covered inputs match, **not identical executable bytes**; different says nothing about newer/older. Same version/path is insufficient. FNV is a diagnostic checksum, not a security boundary. SDKs, linkers, global Cargo configuration, wrappers and dependency contents are not fully captured: this is not hermetic provenance. Cargo's ordinary mtime/cache reuse limitations apply; clean-rebuild when cache validity is in doubt.

### Native familiar click menu

#### Open chat: validated viewer handoff

**API / data flow:** `Context.open_chat` adds `Action::OpenChat` immediately after Copy session ID. `MenuAttachment::open_chat_index` requires the applied binding to match the frozen memo and its exact current target to be a live `djinn` choice; macOS is the only platform gate. There is no GUI installed-capability probe. After tracking, familiar/WindowId, applied binding and available fresh memo are rechecked. `FamiliarControl::open_chat(id, expected: &RuntimeBinding, target: &FocusTarget, incarnation)` uses the shared 32-entry `try_send` queue. Worker `validate_open_chat` authoritatively rechecks graphical support, service instance, exact current target/generation, source incarnation, liveness and ownership before launcher admission; it does not mutate Store selection or presentation.

`chat::Dispatcher` serializes fixed literal `djinn session float --instance … --session …` commands on its own thread. Djinn executable resolution uses only absolute PATH entries, cached after first resolution. Four pending launch slots, pending-target dedupe, two-second completion cooldown and at most 64 recent keys bound admission. CLI acknowledgment waits at most 15 seconds, with no retry; shutdown cancels the owned child and discards queued launches, with a 250 ms dispatcher-drop wait. No GUI process/file/socket I/O, producer-provided command or optimistic attachment-success state is added. Failures log a generic message without child output/target IDs.

**Djinn boundary / edge cases:** exact authenticated record resolution precedes Wisp; the child repeats resolution with the expected gateway generation/session incarnation. Wisp summons a stable live-identity full-chat 70×28 Kitty viewer on the original worker's `Server.Default` handler, not a second execution owner, mini or reopened session. Viewer leases share the original publisher; viewer close releases only that lease, while owner shutdown ends backend access. Missing prerequisites/stale targets fail closed, and acknowledgment means launch only. Initial gateway WebSocket terminal panels are unsupported.

Default-enabled ordinary Chat selection attempts an owned private loopback gateway and bearer record even without Numen; no automatic Wisp/chat action occurs. ### Scene composition

The native window starts at a 96 × 104 logical sprite-only canvas, expands while revealed to 384 × 248 (384 × 144 bubble above the character at `(144, 144)`), and shrinks on hide; no full hidden input area remains. Native atlas cells remain 192 × 208. `--sprite-scale` is finite 0.25–2, default 0.5, affecting artwork only. `dimensions(show, sprite_scale)` rounds sprite bounds upward; shown width is 384, height 144 plus sprite height, otherwise sprite bounds only. `--sprite-scale 1` gives 192 × 208 hidden or 384 × 352 shown. Expansion preserves the sprite anchor when possible and clamps to current monitor bounds near edges. Collapse restores the saved hidden position; an explicit left-drag clears that anchor and commits the current location. This avoids mistaking delayed programmatic window-manager moves for user dragging. Platforms without positioning support are best-effort.

`--scale` remains finite 0.5–4, default 1.5, sizing the entire logical scene including the font. Default requested window size is therefore 144 × 156 hidden or 576 × 372 revealed in logical window units. CPU composition targets actual physical dimensions; the pixels framebuffer and surface match them for 1:1 GPU presentation, not full-canvas nearest upscaling. `Resized` updates both buffer and surface; `ScaleFactorChanged` requests redraw, which reconciles physical dimensions. The centered, aspect-preserving physical scene scale is `min(physical_width / logical_width, physical_height / logical_height)`. Sprite artwork alone is nearest-resampled using pixel centers at scene scale times sprite scale. A half-size character at physical scene scale 2 reproduces the native 192 × 208 pixels.

Low-level `Renderer::new(typeface, font_size)` retains sprite scale 1 for native-unit composition and asset tests. GUI initialization applies the CLI option with `.with_sprite_scale(options.sprite_scale)` and uses the same option for `dimensions` and window sizing. Low-level sprite scales are clamped to 0.25–2 (nonfinite values use 0.5); CLI values outside the finite range are rejected.

`Renderer` rasterizes text at `font_size × physical scene scale` (default 12 logical units, CLI range finite 8–32), independently of sprite scale. `fontdue` supplies real advances, pair kerning, line/baseline metrics and grayscale glyph coverage blended onto ivory. Identity/status clipping and summary wrapping use measured width, with U+2026 `…` truncation. Available vertical space and line height permit up to three summary lines; a larger font can reduce the line count without changing sprite dimensions. The unfocused identity reads “No conversation selected”, not the app/character name. `fontdb` and `fontdue` replace the removed `font8x8` bitmap dependency.

At bubble-enabled GUI initialization, `Typeface::load` prefers installed **SauceCodePro Nerd Font Regular** using `fontdb` system/user-directory discovery. The preference matches the owner's Kitty configuration, but runtime never parses Kitty or copies its font size, nor hardcodes a machine font path. Failure to load the default preference selects embedded OFL **Source Code Pro Regular**, a base font without Nerd icons. `--font-family NAME` instead requires an exact Normal weight/style/stretch family face; `--font-file PATH` directly loads TTF/OTF face 0 (TTC index 0). These options conflict, and explicit missing/invalid selections error rather than falling back. `--no-bubble` bypasses discovery/loading entirely, even for an unusable family/file; CLI validation still applies. Headless/control commands, `check-assets`, and `font-license` never initialize fonts. `font-license` prints the full embedded SIL OFL 1.1 text.

Fonts load/parse once for bubble capability, even while hidden. Views share the parsed `Arc<Font>` via `Typeface::fork`, but each has an independent 512-entry glyph cache at one physical pixel size, cleared on size/DPI change. The atlas is shared as `Arc<SpriteAtlas>`; Window/Pixels, Player, pause, visibility and geometry are private per view. Startup options are inherited; sprite scale, text size and duration can then be edited per view. Unicode/Nerd icons depend on the face; missing glyphs use U+FFFD, then `?`, then `.notdef`. No full shaping, color emoji or fallback chain exists. Font bytes are capped at 32 MiB; system metadata scanning is outside that cap. See [font assets](assets/fonts/README.md).

The bubble reads current base status, not cue state or the player: Idle, Working, Needs your input, Waiting on dependency, Completed, Failed, Cancelled, or Unavailable. Thus Completed remains correct after a one-shot settles to idle, with no historical replay. Missing summary falls back to activity ID; no focus shows Choose a conversation / Not following. Manual/demo overrides explicitly say Preview (Animation preview when unfocused).

The binary embeds `assets/djinn/` PNG and manifest, validates metadata and image dimensions, and caches RGBA frames through `SpriteAtlas`. The temporary global default has ID `djinn` and name Djinn: all tools currently use this fallback. Producer source IDs are not character IDs. A different global default and an explicit application-source `djinn` → character `djinn` mapping are planned, not implemented. The binary never reads the local, gitignored `djinn-artifacts.zip`; its original generation metadata remains unchanged as provenance. Validation rejects missing/duplicate clips, duplicate rows, invalid dimensions, frame counts, timing or loop policies, and malformed/mismatched PNG data.

Frame deadlines use `WaitUntil`, not continuous idle polling. The next wake merges hide, exit, frame, demo and active-motion deadlines. Explicit pause freezes movement and animation, while hide/exit remain scheduled; occluded navigation/celebration can continue independently of drawing. Seeking poses advance only on gated motion ticks. Quiet-period completion needs no wake. Success, failure and waving art play once then settle to idle; only the focused activity's current base resumes afterward. A selection cursor preserves demo/right-click order after one-shots.

## Edge Cases

Current unattached labels supersede the older no-conversation wording above: menu **Unattached** (not Waiting); bubble **Unattached familiar** / **Click for actions** / **Unattached**. Preview labels are unchanged. Unattached is distinct from a bound-but-unavailable exact pin.

- Transparent rendering uses `PostMultiplied` presentation with `REPLACE` blending to preserve straight-alpha bytes. `PixelPerfect` presents the physical-size framebuffer 1:1; only the sprite is nearest-resampled during CPU composition. Aspect-ratio differences may leave padding. Opaque diagnostics blend over black.
- Startup focus is opt-in. macOS accessory activation avoids a Dock icon; left release opens the menu and held movement commits native drag. Non-macOS retains immediate left-drag/focus. Timers and live expression changes never request focus. Transparency, stacking, menu focus and dragging still need desktop acceptance.
- Socket parent must be user-owned/private (use 0700), not a symlink. Only the leaf directory is created, never missing ancestors or chmod of an existing directory. Socket mode is 0600. Active collisions and unsafe paths refuse startup; only an owned, unchanged socket with a refused connection is stale-replaced. Drop unlinks only the owned inode. Abrupt termination may leave a recoverable stale socket.
- Treat received strings as untrusted data, never code or asset paths. Default payloads carry identifiers/state rather than prompts, tool output or credentials. Model memory, execution policy and authorization remain outside Numen.
- Summaries are explicit producer metadata, not generated text: Numen makes no model calls, reads no transcripts and automatically copies no raw prompts. Even a short summary may be sensitive on screen. `--no-bubble` hides only the bubble, not wire/state or headless/status output. The optional Djinn adapter reuses the existing sanitized chat title, not prompts/error files or summarization calls; see [adapter outcomes and limits](README.md#optional-djinn-interactive-adapter).

## Example usage

```sh
cargo run --locked -- run
# Separate terminal:
cargo run --locked -- publish --state working --source build --summary 'Investigating retry backoff' --duration 5
cargo run --locked -- publish --state waiting --attention --reason permission_required
cargo run --locked -- publish --demo
# While producers are connected:
./target/debug/numen status
./target/debug/numen bubbles # Timed reveal, no selection/focus change
./target/debug/numen focus --source djinn --activity chatid --instance producer-1
./target/debug/numen focus --next
./target/debug/numen familiars --offset 0
./target/debug/numen targets --familiar main --offset 0
# Separate eligible connected target required; graphical service only:
./target/debug/numen open --source build --instance worker-2 --activity task --id build-pet
./target/debug/numen bubbles --familiar build-pet
./target/debug/numen go-to-mouse --familiar main build-pet
./target/debug/numen close --familiar build-pet
# Alternatives to the graphical listener:
cargo run --locked -- listen --exit-after 5
cargo run --locked -- run --manual --animation review --paused --always-bubble --exit-after 5
cargo run --locked -- check-assets
```

Use only one listener per socket. Global `--socket PATH` can appear before or after the subcommand; see [Protocol](PROTOCOL.md) for defaults and wire examples.
